あなたはCOBOL→Java移行プロジェクトの設計書リバース担当です。
以下の移行後のJavaソース（1プログラム分）を解析し、「サービス設計書 取込フォーマット」だけを出力してください。
前置き・説明・Markdownの```は出力しないこと。出力はそのまま拡張子なしファイル（UTF-8）として保存します。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 共通ルール
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. ブロックは「#BEGIN 種別」～「#END」。種別は DOC / HIST / SVC / IOLIST / FLOW / PROC / EDIT / ACCESS / OBJ のみ。
2. 「@キー=値」は見出し。キー名は下記の定義どおり（増やさない・変えない）。
3. 「>サブ名」はブロック内の小見出し。その後に @行 → 列名行 → 明細行 と続ける。
4. 列名行は下記の定義どおりに書く。明細は | 区切りで、列数を列名と必ず同じにする（空欄は ||）。
5. 値の中の改行は \n、縦棒は \| 、円記号（バックスラッシュ）は \\ と書く。1つの値を実際の改行で分けない。
6. 「要確認」は、ソースにあるはずの情報が読み取れない時だけ書く。
   該当しないもの（結合がないSQLの別名テーブル、入力のないSQLのInEntity、備考なし 等）は空欄にする。
   SQLに別名が付いていなければ別名テーブルは空欄（「要確認」と書かない）。
7. 出力順: DOC → HIST → SVC → IOLIST → FLOW → PROC → EDIT（DAO呼出・詰め替えごと）→ ACCESS（SQLごと）→ OBJ（Dto/Entityごと）
8. 【最重要】Entity・Dto・Object への値の設定（setter・コンストラクタ・ビルダー・代入・Map.put・リストadd）と
   参照（getter・フィールド参照）は、1つも漏らさず EDIT に書く。書いたものは IOLIST に必ず載せる。
   SQLに関わるものは「Dto→入力Entity(IN)」「入力Entity→SQLパラメータ(SQLIN)」「SQL結果→出力Entity(SQLOUT)」
   「出力Entity→Dto(OUT)」の4段をそろえる。SQL以外の詰め替え（Dto→Dto、Entity→Object、戻り値作成等）は >MAP で書く。
9. 【まとめ禁止】1つのSQL ID ＝ 1つの ACCESS ブロック ＝ PROC の SQL行1行 ＝ 1つの EDIT。
   複数のSQL IDを「／」「・」「,」でつないで1つにしない（例: ×「spn40190_A04／A04b」→ A04 と A04b を別々に書く）。
   条件で呼び分けるSQLも別々に書き、PROC では「～の場合」の行の下にそれぞれ SQL 行を置く。
10.【1行1項目】明細は1行に1項目・1カラム。複数のカラムや項目を「／」「・」でまとめて1行にしない
   （例: ×「BLDG_CD／FLOR_CD／GN_CD」→ 3行に分ける）。OutEntity 等の見出し値も1つずつ（複数あるならSQLを分ける）。
11.【長いソースの場合】1回で書き切れないときは、途中で要約・省略せずに区切りのよいメソッドで止め、
   「続きあり（次は <メソッド名> から）」とだけ最後に書く。依頼者が「続き」と言ったら、その続きのブロックから書く。

■ ブロック定義
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
#BEGIN DOC
@システム名= / @業務ID= / @業務名= / @機能ID= / @機能名= / @処理ID= / @処理名=
@作成者= / @作成日= / @更新者= / @更新日= / @接続先DB=
（各@は1行ずつ。明細なし）
#END

#BEGIN HIST
版数|変更日|変更者|変更区分|変更内容
#END

#BEGIN SVC
項番|サービスID|サービス名|区分|呼出元処理|備考
#END

#BEGIN FLOW
@フロー名=
ID|種別|テキスト|次|列|段|処理No
#END
  ・種別: 開始 / 終了 / 処理概要（処理Noと名称の2マス）/ 処理 / 分岐 / 入出力 / サブ / IF / 人作業 /
          テーブル / データ / ループ始 / ループ終 / イベント / ページ結合
  ・次: 遷移先のID。空欄なら次の行へ進む。終点は「-」。分岐は「ID:ラベル,ID:ラベル」（例 P2:Yes,L2:No）
        データの流れ（点線）は先頭に ~ を付ける（例 ~P1:取得）
  ・列: 0=主系列。エラー処理など横に出す分岐先は 1,2…（同じ列に縦に並べると線が重なるので別の列にする）
  ・段: 通常は空欄（行の順に縦に並ぶ）。テーブル等を処理の横に置くときだけ、横に並べたい行の段番号を書く
  ・テキストは短く（1行15文字程度、必要なら \n で改行）

#BEGIN PROC
@処理No= / @処理名= / @メソッド=
種別|階層|値1|値2|備考
#END
  ・種別: T=文章 / SQL=DAO呼出の箱（値1=SQL ID, 値2=SQL名称） / TH・TD=エラー表（エラーコード｜メッセージ）/ BR=空行
  ・階層: 1=「1.」 2=「1-1.」 3=「DAO実行」等 4=「a.」 5=「c-1.」 6=その下…（字下げの深さ）
  ・【1メソッド＝1ブロック】クラス内のメソッドは public / private を問わず、1メソッドにつき PROC ブロックを1つ作る。
    @メソッド にJavaのメソッド名（例 findPhysicalPlacementIds）、@処理名 にJavadoc1行目を書く。
  ・【処理Noの採番】入口（本来のSPPの入口となるメソッド。通常は1つ）を P100 とする（入口が複数の処理なら P200, P300 …）。
    入口から呼ばれるメソッドは、最初に呼ばれる順に P101, P102, P103 … と枝番を振る（呼び先の呼び先も続き番号）。
    呼ぶ側には「～する（P101参照）」と1行書き、備考に「シート「処理定義」P101参照」と書く（呼び先の中身は展開しない）。
    入口から一度も呼ばれない public メソッドは P901, P902 … とし、@処理名 の先頭に【入口から未使用】と付ける。
  ・【省略禁止】各ブロックの中は要約しない。メソッドの上から順に全ステップを書く。
  ・SQL行は「呼び出している位置」に置き、その直前の T 行に呼ぶ条件（～の場合）を書く。
    SQLを末尾や1か所にまとめて並べない。SQL行の値2（名称）は、そのSQLを呼ぶメソッドのJavadocや
    コメントから取った日本語名にする（SQL IDを繰り返さない）。
  ・【説明なしのSQL連続禁止】SQL行の直前には必ずT行を置き、何のために・どの条件で呼ぶかを書く。
    SQL行の直後には、結果の使い方（件数0件の場合のエラー、取得値を何に使うか）をT行で書く。
  ・【登録・更新・設定の中身は編集定義に書く】処理定義には「～を登録する」等の1行と、備考に参照先だけを書く。
      備考: シート「アクセス定義」「編集定義」参照\n　<編集名>   （SQLなしの値設定は シート「編集定義」参照\n　<編集名>）
    参照した <編集名> と同じ @編集名 の EDIT ブロックを必ず作り、設定した全項目を1項目1行で書く（下記 EDIT の規則）。
    SQLを使わずにオブジェクトの状態を変える処理（「パネル機器状態を更新」「応答電文へ設定」等）も同様に EDIT を作る。
  ・取得件数チェック・例外送出は、エラーコードとメッセージを TH/TD の表で書く（Javadocの「件数が～ならAGZ058E」等も漏らさない）。
  ・備考は「シート「アクセス定義」参照\n　<SQL名称>」の形。編集があるものは「シート「アクセス定義」「編集定義」参照」。
  ・Javaのif/for/whileは「～の場合」「～件数分、以下の処理を行う（ループ処理）」と日本語で書く
  ・例外送出はエラーコード・メッセージを TH/TD の表で書く
  ・備考には参照先を書く（例: シート「アクセス定義」「編集定義」参照\n　作業工程取得）

#BEGIN IOLIST
@見出し=Entity・Object I/O一覧
項番|論理名|物理名|種別|I/O|処理No|編集名|項目数|備考
#END
  ・プログラム内で使う Entity / Dto / Object をすべて1行ずつ（リスト・Mapもその型として1行）
  ・種別: Entity / Dto / Object   I/O: I=値を設定 / O=値を参照 / IO=両方
  ・編集名には、その I/O を書いた EDIT の @編集名 を書く（複数は「 / 」区切り）
  ・I/O があるのに EDIT に書いていないものは、備考に「要確認」と書く

#BEGIN EDIT
@処理No= / @処理名= / @編集名= / @補足=
>IN          ← 引数Dto等 → SQL入力Entity への詰め替え
@件数=単一 または 複数
項番|項目|項目詳細|設定元|設定値|備考
>SQLIN       ← SQL入力Entity → SQLパラメータ（バインド変数）
@SQLID=
項番|Entity|項目|SQLパラメータ|対応カラム|備考
>SQLOUT      ← SQL結果カラム → SQL出力Entity
@SQLID=
項番|結果カラム|別名|Entity|項目|備考
>OUT         ← SQL出力Entity → 出力Dto等 への詰め替え
@件数=単一 または 複数
項番|項目|項目詳細|設定元|設定値|備考
>MAP         ← SQL以外の詰め替え（何個でも）
@見出し= / @編集元= / @編集先= / @件数=
項番|項目|項目詳細|設定元|設定値|備考
#END
  ・DAO呼出1回につき EDIT を1つ作り、IN → SQLIN → SQLOUT → OUT の順に書く
  ・@編集名 は処理定義の備考で参照している名前と完全に一致させる（SQL名称と同じにする）
  ・登録・更新（INSERT/UPDATE）は、IN に「Dto等→Entity」の全項目、SQLIN に「Entity→カラム」の全項目を書き、
    設定値は出所が分かる形にする（入力電文.パスID / 取得結果.収容位置 / システム日時 / 固定値 '1' / 採番した次位置 等）。
    UPDATE・DELETE の対象条件のパラメータも SQLIN に書き、備考に「条件」と書く。
  ・SQLを使わない値設定（Dto・応答電文・Entityのsetter）は >MAP で、@編集元・@編集先と全項目を書く
  ・SQL以外の詰め替えは、意味のまとまりごとに EDIT を作って >MAP で書く
  ・SQLパラメータは MyBatis等の書式どおり（#{xxx}、:xxx、? の場合は順番）
  ・対応カラム・結果カラムは「別名.物理名」で書く（ACCESSの別名とそろえる）
  ・項番は 1, 1-1, 1-2 …（親子関係は項番で表す。値の先頭にスペースを入れて字下げしない）

#BEGIN ACCESS
@処理No= / @アクセス名= / @SQLID= / @概要=
>ITEM
@見出し=項目（取得） / @処理種別=取得 / @件数= / @InEntity= / @OutEntity=
項番|別名テーブル|論理名|物理名|編集仕様|備考
>TABLE
別名テーブル|論理名|物理名|備考
>JOIN      ← 結合テーブル1つにつき1回（番号①②…は自動）
@結合方法= / @別名テーブル= / @論理名= / @物理名=
論理演算子|結合方法|左別名|左論理名|左物理名|条件|右別名|右論理名|右物理名|備考
>WHERE     ← 抽出条件1グループにつき1回
@論理演算子= / @概要=
論理演算子|別名テーブル|論理名|物理名|編集仕様|備考
>SUBQ      ← サブクエリがある場合
@処理種別=
項番|別名テーブル|論理名|物理名|編集仕様|備考
>SORT      ← ORDER BY がある場合
項番|別名テーブル|論理名|物理名|順序|備考
#END
  ・@SQLID はソースどおりのSQL ID（1つだけ）。@処理No はそのSQLを呼ぶメソッドの処理No（P101 等）
  ・INSERT / UPDATE は >ITEM の @見出し=項目（登録）または項目（更新）、@処理種別=登録/更新 とし、
    設定する全カラムを1行ずつ書き、編集仕様に設定値（= 入力電文.xxx / = SYSDATE / = '1' 等）を書く。
    UPDATE / DELETE は >WHERE に対象条件を必ず書く。
  ・SQLの別名（a,b,c…）はソースのSQLどおり。論理名はエンティティのコメント/Javadocから

#BEGIN OBJ
@論理名称= / @物理名称=
項番|論理名|物理名|型|備考
#END
  ・ネストしたクラスは展開し、項番を 3, 3-1, 3-2 … として親子関係を表す（字下げしない）
  ・論理名はJavadoc（/** ～ */）から
